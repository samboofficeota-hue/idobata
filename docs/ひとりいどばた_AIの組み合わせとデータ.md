> 作成日：2026-11-01

## 0. ひとことで

- 本人に見える顔は**ファシリテーターとAI参加者の2つだけ。** 裏では、役割ごとに別のAIを呼ぶ（全部で7つの役。効果の見通しを受け持つ根拠係は、あとで設計する）
- **進行はプログラムが持つ。** AIはそれぞれの仕事をするだけで、AI同士は直接やりとりしない
- **ボードが共有の黒板。** すべてのAIはボードを読み、ボードに書く。書く前に、形とIDと版をプログラムが確かめる
- 1回の発言で呼ぶAIは、ふつう**ファシリテーターと書記の2つ**（同時に呼ぶ）。ほかはきっかけがあったときだけ
- **確定は本人の操作だけ。** AIが書けるのは付箋と「案」まで

## 1. 決まったこと

| 項目 | 決定 |
|---|---|
| 見える顔 | ファシリテーター（全段階で同じ1人）と、アイデア出しで加わるAI参加者の2つ |
| AI参加者の出方 | まずは〔ほかの人のアイデアも聞く〕を押すと、それぞれが付箋でアイデアを出す形から始める。AI参加者と会話する形は、そのあとに考える |
| 効果の見通し（16）と根拠係 | **あとで、RAG（資料や根拠を探してAIに渡す仕組み）の設計と合わせて考える** |
| 話している最中の文字表示 | 最初の版では出さない。話し終えてから文字にし、付箋にする（今の音声入力 `gpt-transcribe` の方式のまま） |
| ファシリテーターと書記 | 同時に呼ぶ（型C。[`設計の考え方`](./ひとりいどばた_設計の考え方.md) 5.2） |

## 2. 組み立ての柱

| # | 柱 | 理由 |
|---|---|---|
| 1 | **本人に見える顔は2つだけ。** 裏では役割ごとに別のAIを呼ぶ | 顔が増えると、誰と話しているかわからなくなる。裏で役割を分けると、それぞれの指示文が短く、質が安定する |
| 2 | **進行はプログラムが持つ。** 段階の切り替え、どのAIを動かすか、どの付箋を掘り下げるかの候補選びは、プログラムが決める | 予測でき、試験もできる。Orality も、会議室の話者の偏りの調整も、この形 |
| 3 | **ボードが共有の黒板。** AI同士は直接やりとりしない | 同時に動くAIのずれを、1か所で管理できる |
| 4 | **本人を待たせるのはファシリテーターだけ。** ほかのAIは裏で動き、結果はあとから届く | 返事の速さを守る |
| 5 | **確定は本人の操作だけ。** 課題・望ましい姿・解決案などは、本人が〔これで決める〕を押して確定する | 「決めるのは本人」をデータの作りで守る |

## 3. 全体の形

```
本人 ── 発言 ──▶ 進行役（プログラム）──┬──▶ ファシリテーター ──▶ 返事（ここだけ待たせる）
 ▲    ボタン ──▶                       └──▶ 書記 ─────────────▶ 付箋の追加・更新・印
 │    付箋を直す                             （同時に呼ぶ）
 │                        きっかけごとに
 │                        ├──▶ 整理係   （〔まとめる〕を押したとき）
 │                        ├──▶ 点検係   （課題や望ましい姿の候補が出たとき）
 │                        ├──▶ AI参加者 （〔ほかの人のアイデアも聞く〕を押したとき）
 │                        ├──▶ 編集者   （まとめに入ったとき）
 │                        └──▶ 根拠係   （あとで設計する）
 │                                   │
 │                                   ▼  すべての出力は、形とIDと版を確かめてから反映
 └──── 画面 ◀──── ボード（共有の黒板）＋ 確定事項
```

## 4. 役割

### 4.1 7つの役

| 役 | 見えるか | 仕事 | 動くきっかけ | 読むもの | 書くもの | 重さ |
|---|---|---|---|---|---|---|
| **ファシリテーター** | 見える | 問う・案内する・次の段階を提案する。段階ごとに指示を切り替える | 本人の発言のたび | 会話、ボードの要約、点検の結果、プログラムが選んだ掘り下げ候補、（下準備では）お題の資料 | 返事（1〜2文）、触れた付箋のID、「次へ進めそう」の合図 | 中〜上。速さ優先 |
| **書記** | 見えない | 発言を付箋にする。足りないものの印、食い違いの印。段階に合わせて付箋の種類を変える | 本人の発言のたび（ファシリテーターと同時） | 今の発言、今ある付箋の一覧（ID付き） | 付箋の差分（追加・更新・印） | 小〜中。速さ優先 |
| **整理係** | 見えない | グループ分けと名前付けの案。名前は本人の言葉を優先する。「その他」を許す | 〔まとめる〕を押したとき | すべての付箋 | 整理の案 | 上 |
| **点検係** | 見えない | 課題の点検、望ましい姿の指標の有無、課題と望ましい姿のつながり、解決案と課題のつながり | 候補が出たとき | 候補の文、根拠の付箋、確定事項 | 点検の結果 | 上 |
| **AI参加者** | 見える | 別の参加者としてアイデアを出す。課題を問い直す | 〔ほかの人のアイデアも聞く〕を押したとき | 確定した課題・望ましい姿、本人のアイデア | アイデアの付箋（色を分ける）、一言のコメント | 中 |
| **編集者** | 見えない | ストーリーの下書き | まとめに入ったとき、本人が頼んだとき | 確定事項、根拠の付箋 | ストーリーの案 | 上 |
| **根拠係** | 見えない | 似た事例を根拠集から探し、効果の幅を出典つきでまとめる。なければ「見つからない」 | 解決案が確定したとき | 確定事項（特に指標）、根拠集 | 効果の見通しの案 | **あとで設計する**（RAG と合わせて） |

「重さ」は、使うAIのモデルの大きさの目安。具体的なモデルは、試して決める。

### 4.2 点検係の結果の見せ方

本人に直接「ダメ出し」はしない。2通りで使う。

- ボードの課題カードの横に、点検項目を小さく表示する（例：誰が ✓、場面 ✓、どれくらい ？）。何が足りないかが本人にも見える
- ファシリテーターの次の問いの材料にする（足りない点を1つずつ問う）

点検項目は [`体験の流れ`](./ひとりいどばた_体験の流れ.md) 3.2・3.3。

### 4.3 下準備で資料をどう渡すか

- お題の資料が短ければ、**丸ごと**ファシリテーターの指示文の先頭（毎回変わらない部分）に入れる。キャッシュが効く
- 長ければ、関係する部分を探して渡す。探し方は、根拠係と同じく **RAG の設計と合わせて考える**
- どちらの場合も、資料にないことは「資料にはありません」と答える

## 5. 段階ごとに、どの役が動くか

●＝毎回の発言で動く、○＝きっかけがあったときだけ、－＝動かない

| 段階 | ファシリテーター | 書記 | 整理係 | 点検係 | AI参加者 | 編集者 | 根拠係 |
|---|---|---|---|---|---|---|---|
| 下準備（1〜3） | ●（資料の範囲で答える） | ○（3で「気になったこと」） | － | － | － | － | － |
| 意見出し（4〜6） | ●（広げる・掘り下げる） | ●（意見の付箋） | ○ | － | － | － | － |
| 課題整理（7〜9） | ●（課題の点検の問い） | ●（課題の候補） | ○（〔まとめる〕） | ○（課題の候補が出たら） | － | － | － |
| ゴール設定（10〜11） | ●（望ましい姿を描く問い） | ●（望ましい姿の候補） | － | ○（指標・つながり） | － | － | － |
| アイデア出し（12〜14） | ●（進行） | ●（アイデアの付箋） | ○ | ○（選んだ案と課題のつながり） | ○（ボタン） | － | － |
| まとめ（15〜17） | ●（確かめの問い） | － | － | － | － | ○（入ったら） | （あとで） |

**1回の発言で呼ぶAIは、ふつう2つ**（ファシリテーターと書記）。

## 6. 動き方

### 6.1 1回の発言の流れ

```
1. 本人が話す → 文字にする → 発言として保存
2. 進行役が、ファシリテーターに渡すものを用意する
     ・ボードの要約（その時点の版）
     ・掘り下げ候補（印が付いた付箋、まだ聞いていない付箋。消した付箋は除く）
     ・前回までの点検の結果
3. ファシリテーターと書記を同時に呼ぶ
4. ファシリテーターの返事を確かめる（形が正しいか、触れた付箋のIDが実在するか）→ 画面に出す
5. 書記の差分を確かめる（形、ID、付箋の版）→ 本人が直した付箋は上書きしない → ボードに反映
6. 書記が「課題の候補」などを作ったら、点検係を裏で呼ぶ → 結果は次のファシリテーターの問いに使う
```

- 点検の結果は、1回遅れてファシリテーターに届く。課題を言った直後の返事は「受け止めて、最初の1点を問う」にとどめ、次の問いから点検の結果を使う
- 同じ人の発言が続けて届いたら、書記は順番に処理する（追い越さない）
- 書記や点検係が失敗しても、会話は止めない

### 6.2 きっかけの一覧

| きっかけ | 動くもの |
|---|---|
| 本人の発言 | ファシリテーター、書記（同時） |
| 書記が候補（課題・望ましい姿）を作った | 点検係（裏で） |
| 〔まとめる〕 | 整理係 |
| 〔ほかの人のアイデアも聞く〕 | AI参加者 |
| 〔これで決める〕 | プログラムが確定事項を書き換える。必要なら点検係（つながりの確認） |
| 〔次へ〕〔戻る〕 | プログラムが段階を切り替え、ボードの写しを保存。ファシリテーターがその段階の最初の一言を出す |
| まとめに入った | 編集者 |
| 付箋の〔直す〕〔消す〕、ボードの〔戻す〕 | プログラムだけ（AIは動かない） |

### 6.3 段階を進むのに必要なもの

ファシリテーターが「次に進みましょうか」と提案し、本人が〔次へ〕を押す。次のものがそろっていなければ、プログラムが進ませない（そろっていないことを本人に伝える）。

| 段階を出るとき | 必要なもの |
|---|---|
| 下準備 → 意見出し | なし（お題の理解の一言はあったほうがよいが、必須にしない） |
| 意見出し → 課題整理 | 意見の付箋が1枚以上 |
| 課題整理 → ゴール設定 | 課題（1文）の確定 |
| ゴール設定 → アイデア出し | 望ましい姿（1文）の確定。指標はあったほうがよいが、必須にしない |
| アイデア出し → まとめ | 解決案の確定 |
| まとめ → 終わり | ストーリーの確定 |

戻るのはいつでもできる。

### 6.4 指示文の並び

会議室で決めた並び（[`いどばた会議室_設計思想.md`](./いどばた会議室_設計思想.md) 原則7）を引き継ぐ。キャッシュは先頭から同じ部分にしか効かないため。

```
変わらない先頭（役割、ルール、お題、資料）
 → このセッションで固まったもの（確定事項）
 → 会話の履歴
 → 毎回変わる末尾（ボードの要約、掘り下げ候補、点検の結果、今の段階）
```

### 6.5 AIの出力の形（たたき台）

**ファシリテーター**

```json
{
  "read": "本人の発言の読み取り（本人には見せない）",
  "content": "返事。1〜2文で、問いで終える",
  "refs": ["note_12"],
  "questionType": "掘り下げ:理由",
  "suggestAdvance": false
}
```

**書記**

```json
{
  "ops": [
    { "op": "add", "kind": "意見.経験", "text": "週3日、子どもが一人で過ごしている", "quote": "週に3日くらいは一人で…", "sourceMessageId": "msg_5" },
    { "op": "update", "noteId": "note_3", "baseVersion": 2, "text": "…" },
    { "op": "flag", "noteId": "note_4", "flag": "理由がない" },
    { "op": "flag", "noteId": "note_4", "flag": "食い違い", "relatedNoteId": "note_7", "confidence": 8 }
  ]
}
```

**点検係**

```json
{
  "target": "issue",
  "targetVersion": 3,
  "items": [
    { "point": "誰が", "status": "ok" },
    { "point": "どれくらい", "status": "不足", "hint": "頻度や人数がまだない" }
  ]
}
```

**整理係**

```json
{
  "groups": [
    { "name": "送り迎えの負担", "nameSource": "本人の言葉", "noteIds": ["note_1", "note_4"] }
  ],
  "other": ["note_9"]
}
```

**AI参加者**

```json
{
  "persona": "member1",
  "ideas": [{ "text": "…" }],
  "comment": "一言",
  "challenge": "（任意）課題への問い直し"
}
```

## 7. データの持ち方

### 7.1 全体

```
お題（Theme）           ─ ホストが用意：名前、資料（スライド・テキスト）、根拠集（あとで）
 └ セッション（Session） ─ 1人・1日：今の段階、確定事項、ボードの版
     ├ 発言（Message）        ─ 誰が（本人・ファシリテーター・AI参加者）、本文、段階、音声か文字か
     ├ 付箋（Note）           ─ ボードの中身
     ├ 整理の案（Arrangement）─ グループ分けの案と、採用したか
     ├ 点検の結果（Check）    ─ 何を点検し、何が足りないか
     ├ ボードの写し（Snapshot）─ 段階の切り替え・整理の採用・確定のたびに保存。戻すときに使う
     ├ AIの実行記録（AgentRun）─ どの役が、何をきっかけに、何を出し、確かめに通ったか、速さ、費用
     └ ドキュメント（Document）─ 手元に残る成果物。届けた記録
```

### 7.2 付箋（いちばん大事なデータ）

| 項目 | 中身 |
|---|---|
| ID・版 | 本人とAIの編集がぶつかったとき、古い版を前提にしたAIの操作を捨てるため |
| 種類 | 気になったこと／意見（経験・気持ち・困りごと・考え）／課題の候補／望ましい姿の候補／アイデア |
| 本文 | 短い一文 |
| 引用・元の発言 | 元の発言のどの部分から作ったか（AIが作った付箋は必須） |
| 作った人 | 本人／書記／AI参加者（どの人か） |
| 本人が直した | 直したら、AIは上書きしない |
| 印 | 理由がない・具体例がない・気持ちがない・食い違い（相手の付箋、自信の度合い） |
| 話した回 | 色分けに使う |
| グループ | 整理の案を採用したときに入る |
| 状態 | ふつう／ごみ箱（消しても戻せる） |
| 段階 | どの段階で作られたか |
| 掘り下げた回数 | ファシリテーターが触れた回数。候補選びと、偏りの確認に使う |

### 7.3 確定事項（セッションの中に持つ）

| 項目 | 中身 |
|---|---|
| お題の理解 | 一言 |
| 現状 | 文 |
| 課題 | 1文、根拠の付箋のID |
| 望ましい姿 | 1文、指標 |
| 解決案 | 文、理由、元にしたアイデアの付箋のID（AI参加者の案か本人の案か） |
| ストーリー | 本人が確定した文 |
| 効果の見通し | 事例、効果の幅、出典、前提（AIが作ったと明記）。**あとで設計する** |

どの項目も、**本人が〔これで決める〕を押したときだけ書き換わり**、前の版も残す（戻すため、あとで経緯を見るため）。

### 7.4 AIの実行記録

| 項目 | 中身 |
|---|---|
| 役・きっかけ | どの役が、何をきっかけに動いたか |
| 入力の版 | どの版のボードを読んだか、どの版の指示文か |
| モデル | 使ったモデル |
| 出力 | AIが返したそのままの出力 |
| 確かめの結果 | 反映したか、捨てたか（理由） |
| 速さ・費用 | かかった時間、トークン数、キャッシュに乗った量 |

### 7.5 データの決まり

- **AIの出力は、決まった形に合っているか、指している付箋のIDが実在するか、版が古くないかを確かめてから反映する。** 形の定義は、画面とサーバーで共有する
- 付箋は、セッションの中に埋め込まず、**別のまとまり（コレクション）で持つ。** 書記と本人が同時に書き換えるので、1枚ずつ版を管理するため
- 音声は保存しない（文字だけ残す。会議室と同じ）
- **AIの実行記録は必ず残す。** 費用と速さを測るためと、「どの付箋をどれだけ掘り下げたか」の偏り（誘導）をあとで確かめるため
- 何日残すかは未決（会議室は30日）
