## 0. ひとことで

- 本人に見える顔は**ファシリテーターとAI参加者の2つだけ。** 裏では、役割ごとに別のAIを呼ぶ（全部で7つの役）
- **資料係**は顔を持たず、関連する調査やレポートから、**ファシリテーターに事実を助言する。** 事実が本人に届くのは、ファシリテーターの言葉を通してだけで、必ず出典を添える
- **進行はプログラムが持つ。** AIはそれぞれの仕事をするだけで、AI同士は直接やりとりしない
- **ボードが共有の黒板。** すべてのAIはボードを読み、ボードに書く。書く前に、形とIDと版をプログラムが確かめる
- 1回の発言で呼ぶAIは、ふつう**ファシリテーターと書記の2つ**（同時に呼ぶ）。ほかはきっかけがあったときだけ
- **確定は本人の操作だけ。** AIが書けるのは付箋と「案」まで

## 1. 決まったこと

| 項目 | 決定 |
|---|---|
| 見える顔 | ファシリテーター（全段階で同じ1人）と、アイデア出しで加わるAI参加者の2つ |
| AI参加者の出方 | まずは〔ほかの人のアイデアも聞く〕を押すと、それぞれが付箋でアイデアを出す形から始める。AI参加者と会話する形は、そのあとに考える |
| 資料係 | **顔を持たない。ファシリテーターに事実を助言する裏の役。** 資料は、お題ごとに関連する調査の結果やレポートを入れる（4.3） |
| 意見出しでの事実 | 本人が質問したときだけ示す。自分の考えを出し切る前に、事実で考えを寄せないため。プログラムで守る（資料の抜粋を渡さない） |
| 効果の見通し（16） | 資料係が受け持つ。中身は、RAG（資料を探してAIに渡す仕組み）の設計と合わせて考える |
| 話している最中の文字表示 | 最初の版では出さない。話し終えてから文字にし、付箋にする（今の音声入力 `gpt-transcribe` の方式のまま） |
| ファシリテーターと書記 | 同時に呼ぶ（型C。[`設計の考え方`](./ひとりいどばた_設計の考え方.md) 5.2） |

## 2. 組み立ての柱

| # | 柱 | 理由 |
|---|---|---|
| 1 | **本人に見える顔は2つだけ。** 裏では役割ごとに別のAIを呼ぶ | 顔が増えると、誰と話しているかわからなくなる。裏で役割を分けると、それぞれの指示文が短く、質が安定する |
| 2 | **進行はプログラムが持つ。** 段階の切り替え、どのAIを動かすか、どの付箋を掘り下げるかの候補選びは、プログラムが決める | 予測でき、試験もできる。Orality も、会議室の話者の偏りの調整も、この形 |
| 3 | **ボードが共有の黒板。** AI同士は直接やりとりしない | 同時に動くAIのずれを、1か所で管理できる |
| 4 | **本人を待たせるのはファシリテーターだけ。** ほかのAIは裏で動き、結果はあとから届く | 返事の速さを守る |
| 5 | **確定は本人の操作だけ。** 課題・望ましい姿・解決案などは、本人が〔これで決める〕を押して確定する | 「決めるのは本人」をデータの作りで守る |

## 3. 全体の形

```
本人 ── 発言 ──▶ 進行役（プログラム）──┬──▶ ファシリテーター ──▶ 返事（ここだけ待たせる）
 ▲    ボタン ──▶                       └──▶ 書記 ─────────────▶ 付箋の追加・更新・印
 │    付箋を直す                             （同時に呼ぶ）
 │                        きっかけごとに
 │                        ├──▶ 整理係   （〔まとめる〕を押したとき）
 │                        ├──▶ 点検係   （課題や望ましい姿の候補が出たとき）
 │                        ├──▶ AI参加者 （〔ほかの人のアイデアも聞く〕を押したとき）
 │                        ├──▶ 編集者   （まとめに入ったとき）
 │                        └──▶ 資料係   （課題・望ましい姿の案、アイデアが出たとき）
 │                                     └ 事実のメモ ──▶ 次のファシリテーターの問いに使う
 │                                   │
 │                                   ▼  すべての出力は、形とIDと版を確かめてから反映
 └──── 画面 ◀──── ボード（共有の黒板）＋ 確定事項
```

## 4. 役割

### 4.1 7つの役

| 役 | 見えるか | 仕事 | 動くきっかけ | 読むもの | 書くもの | 重さ |
|---|---|---|---|---|---|---|
| **ファシリテーター** | 見える | 問う・案内する・次の段階を提案する。段階ごとに指示を切り替える。事実を示すときは出典を添える | 本人の発言のたび | 会話、ボードの要約、点検の結果、プログラムが選んだ掘り下げ候補と問いの種類、お題の資料、資料の抜粋、資料係のメモ | 返事（1〜2文。事実を示すときは3文まで）、触れた付箋のID、示した資料の記号、「次へ進めそう」の合図 | 中〜上。速さ優先 |
| **書記** | 見えない | 発言を付箋にする。足りないものの印、食い違いの印。段階に合わせて付箋の種類を変える | 本人の発言のたび（ファシリテーターと同時） | 今の発言、今ある付箋の一覧（ID付き） | 付箋の差分（追加・更新・印） | 小〜中。速さ優先 |
| **整理係** | 見えない | グループ分けと名前付けの案。名前は本人の言葉を優先する。「その他」を許す | 〔まとめる〕を押したとき | すべての付箋 | 整理の案 | 上 |
| **点検係** | 見えない | 課題の点検、望ましい姿の指標の有無、課題と望ましい姿のつながり、解決案と課題のつながり | 候補が出たとき | 候補の文、根拠の付箋、確定事項 | 点検の結果 | 上 |
| **AI参加者** | 見える | 別の参加者としてアイデアを出す。課題を問い直す | 〔ほかの人のアイデアも聞く〕を押したとき | 確定した課題・望ましい姿、本人のアイデア | アイデアの付箋（色を分ける）、一言のコメント | 中 |
| **編集者** | 見えない | ストーリーの下書き | まとめに入ったとき、本人が頼んだとき | 確定事項、根拠の付箋 | ストーリーの案 | 上 |
| **資料係** | 見えない | 関連する調査やレポートから、ファシリテーターに事実を助言する。事実ごとに出典と、資料からそのまま抜き出した部分を付ける。意見は書かない。まとめでは効果の見通しを受け持つ（あとで設計） | 課題の案・望ましい姿の案・アイデアが出たとき | プログラムが探した資料の抜粋、確定事項 | 事実のメモ（ファシリテーターだけが読む） | 上 |

「重さ」は、使うAIのモデルの大きさの目安。具体的なモデルは、試して決める。

### 4.2 点検係の結果の見せ方

本人に直接「ダメ出し」はしない。2通りで使う。

- ボードの課題カードの横に、点検項目を小さく表示する（例：誰が ✓、場面 ✓、どれくらい ？）。何が足りないかが本人にも見える
- ファシリテーターの次の問いの材料にする（足りない点を1つずつ問う）

点検項目は [`体験の流れ`](./ひとりいどばた_体験の流れ.md) 3.2・3.3。

### 4.3 資料の渡し方（資料係）

資料は2種類ある。

| 資料 | 中身 | 渡し方 |
|---|---|---|
| お題の資料 | ホストが用意したスライド・テキスト | 短いので、**丸ごと**ファシリテーターの指示文の先頭（毎回変わらない部分）に入れる。キャッシュが効く |
| 関連資料 | お題に関連する調査の結果やレポート（ホストがお題ごとに入れる） | 長いので、**関係する部分（抜粋）を探して渡す** |

関連資料は、2段で渡す。

```
① 検索（プログラム・毎回）
   本人の発言（質問のときは質問の言葉だけ）や課題の案から、関係しそうな抜粋を探す
   → そのままファシリテーターに渡す（待ち時間は増えない）
   ※ 意見出しの段階では、本人が質問したときだけ渡す

② 資料係（AI・裏で・1回遅れ）
   課題の案・望ましい姿の案・アイデアが出たとき、抜粋を読み、
   「点検の不足を埋める手がかり」「指標の目安」「似た事例と続けるうえでの課題」を事実のメモにする
   → 次のファシリテーターの問いに使われる
```

ファシリテーターが事実を言うときの決まり：

- 渡された抜粋と資料係のメモにあることだけを使い、出典を添える。抜粋にないことは「関連資料には見当たりません」と言う
- 課題整理とゴール設定では、点検の「不足」を埋める手がかりになるときだけ、事実を1つ示してから本人の考えを問う（例：「資料では〜とあります（資料：〇〇）。あなたの身近ではどうですか？」）
- 事実で本人の考えを決めつけない。「だから〜が課題です」とは言わない

プログラムが確かめること：

- ファシリテーターが示した出典が、本当に渡した抜粋か（渡していないものは外す）
- 資料係が付けた引用が、抜粋の中に本当にあるか（なければ、その事実を捨てる）

ボードでは、ファシリテーターが示した事実を「資料から」の欄に出典つきで並べる。課題の点検の「根拠」にも使える。

試作の検索は、漢字・カタカナの2文字の重なりで点数を付ける簡単なもの。本番は、文の意味で探す仕組み（RAG）に置き換える（8章）。

## 5. 段階ごとに、どの役が動くか

●＝毎回の発言で動く、○＝きっかけがあったときだけ、－＝動かない

| 段階 | ファシリテーター | 書記 | 整理係 | 点検係 | AI参加者 | 編集者 | 資料係 |
|---|---|---|---|---|---|---|---|
| 下準備（1〜3） | ●（資料の範囲で答える） | ○（3で「気になったこと」） | － | － | － | － | 検索のみ（質問への答えに使う抜粋） |
| 意見出し（4〜6） | ●（広げる・掘り下げる） | ●（意見の付箋） | ○ | － | － | － | 本人が質問したときだけ検索 |
| 課題整理（7〜9） | ●（課題の点検の問い） | ●（課題の候補） | ○（〔まとめる〕） | ○（課題の候補が出たら） | － | － | ○（課題の案が出たら） |
| ゴール設定（10〜11） | ●（望ましい姿を描く問い） | ●（望ましい姿の候補） | － | ○（指標・つながり） | － | － | ○（望ましい姿の案が出たら） |
| アイデア出し（12〜14） | ●（進行） | ●（アイデアの付箋） | ○ | ○（選んだ案と課題のつながり） | ○（ボタン） | － | ○（アイデアが出たら） |
| まとめ（15〜17） | ●（確かめの問い） | － | － | － | － | ○（入ったら） | 効果の見通し（あとで設計） |

**1回の発言で呼ぶAIは、ふつう2つ**（ファシリテーターと書記）。

## 6. 動き方

### 6.1 1回の発言の流れ

```
1. 本人が話す → 文字にする → 発言として保存
2. 進行役が、ファシリテーターに渡すものを用意する
     ・ボードの要約（その時点の版）
     ・掘り下げ候補（印が付いた付箋、まだ聞いていない付箋。消した付箋は除く）
     ・前回までの点検の結果
     ・問いの種類（意見出しでは、3回に1回は「広げる」。プログラムが決める）
     ・資料の抜粋（検索の結果）と、資料係のメモ
3. ファシリテーターと書記を同時に呼ぶ
4. ファシリテーターの返事を確かめる（形が正しいか、触れた付箋のIDが実在するか、示した資料が渡した抜粋か）→ 画面に出す
5. 書記の差分を確かめる（形、ID、付箋の版、引用が発言の中にあるか）→ 本人が直した付箋は上書きしない → ボードに反映
6. 書記が「課題の候補」などを作ったら、点検係と資料係を裏で呼ぶ → 結果は次のファシリテーターの問いに使う
7. ファシリテーターが直前の発言を掘り下げたときは、その発言から書記が作った付箋に「掘り下げた」を数える
```

- 点検の結果は、1回遅れてファシリテーターに届く。課題を言った直後の返事は「受け止めて、最初の1点を問う」にとどめ、次の問いから点検の結果を使う
- 同じ人の発言が続けて届いたら、書記は順番に処理する（追い越さない）
- 書記や点検係が失敗しても、会話は止めない

### 6.2 きっかけの一覧

| きっかけ | 動くもの |
|---|---|
| 本人の発言 | ファシリテーター、書記（同時） |
| 書記が候補（課題・望ましい姿）を作った | 点検係と資料係（裏で） |
| 書記がアイデアの付箋を作った | 資料係（裏で。似た事例を探す） |
| 〔まとめる〕 | 整理係 |
| 〔ほかの人のアイデアも聞く〕 | AI参加者 |
| 〔これで決める〕 | プログラムが確定事項を書き換える。必要なら点検係（つながりの確認） |
| 〔次へ〕〔戻る〕 | プログラムが段階を切り替え、ボードの写しを保存。ファシリテーターがその段階の最初の一言を出す |
| まとめに入った | 編集者 |
| 付箋の〔直す〕〔消す〕、ボードの〔戻す〕 | プログラムだけ（AIは動かない） |

### 6.3 段階を進むのに必要なもの

ファシリテーターが「次に進みましょうか」と提案し、本人が〔次へ〕を押す。次のものがそろっていなければ、プログラムが進ませない（そろっていないことを本人に伝える）。

| 段階を出るとき | 必要なもの |
|---|---|
| 下準備 → 意見出し | なし（お題の理解の一言はあったほうがよいが、必須にしない） |
| 意見出し → 課題整理 | 意見の付箋が1枚以上 |
| 課題整理 → ゴール設定 | 課題（1文）の確定 |
| ゴール設定 → アイデア出し | 望ましい姿（1文）の確定。指標はあったほうがよいが、必須にしない |
| アイデア出し → まとめ | 解決案の確定 |
| まとめ → 終わり | ストーリーの確定 |

戻るのはいつでもできる。

### 6.4 指示文の並び

会議室で決めた並び（[`いどばた会議室_設計思想.md`](./いどばた会議室_設計思想.md) 原則7）を引き継ぐ。キャッシュは先頭から同じ部分にしか効かないため。

```
変わらない先頭（役割、ルール、お題、資料）
 → このセッションで固まったもの（確定事項）
 → 会話の履歴
 → 毎回変わる末尾（ボードの要約、掘り下げ候補、点検の結果、今の段階）
```

## 7. データの持ち方

### 7.1 全体

```
お題（Theme）           ─ ホストが用意：名前、お題の資料（スライド・テキスト）
 ├ 関連資料（Source）    ─ 調査の結果やレポート：名前、発行元、年、種類（調査・統計・事例・研究）
 │  └ 抜粋（Chunk）     ─ 検索の単位：記号（d2-1 など）、本文、ページ。本番は意味で探すための数値（埋め込み）も持つ
 └ セッション（Session） ─ 1人・1日：今の段階、確定事項、ボードの版
     ├ 発言（Message）        ─ 誰が（本人・ファシリテーター・AI参加者）、本文、段階、音声か文字か
     ├ 付箋（Note）           ─ ボードの中身
     ├ 整理の案（Arrangement）─ グループ分けの案と、採用したか
     ├ 点検の結果（Check）    ─ 何を点検し、何が足りないか
     ├ 資料係のメモ（Advice） ─ どの段階で、どの抜粋から、どんな事実を、何に使えるか
     ├ 示した事実（Cited）    ─ ファシリテーターが本人に示した抜粋の記号。ボードの「資料から」に並ぶ
     ├ ボードの写し（Snapshot）─ 段階の切り替え・整理の採用・確定のたびに保存。戻すときに使う
     ├ AIの実行記録（AgentRun）─ どの役が、何をきっかけに、何を出し、確かめに通ったか、速さ、費用
     └ ドキュメント（Document）─ 手元に残る成果物。届けた記録
```

### 7.2 付箋（いちばん大事なデータ）

| 項目 | 中身 |
|---|---|
| ID・版 | 本人とAIの編集がぶつかったとき、古い版を前提にしたAIの操作を捨てるため |
| 種類 | 気になったこと／意見（経験・気持ち・困りごと・考え）／課題の候補／望ましい姿の候補／アイデア |
| 本文 | 短い一文 |
| 引用・元の発言 | 元の発言のどの部分から作ったか（AIが作った付箋は必須） |
| 作った人 | 本人／書記／AI参加者（どの人か） |
| 本人が直した | 直したら、AIは上書きしない |
| 印 | 理由がない・具体例がない・気持ちがない・食い違い（相手の付箋、自信の度合い） |
| 話した回 | 色分けに使う |
| グループ | 整理の案を採用したときに入る |
| 状態 | ふつう／ごみ箱（消しても戻せる） |
| 段階 | どの段階で作られたか |
| 掘り下げた回数 | ファシリテーターが触れた回数。候補選びと、偏りの確認に使う |

### 7.3 確定事項（セッションの中に持つ）

| 項目 | 中身 |
|---|---|
| お題の理解 | 一言 |
| 現状 | 文 |
| 課題 | 1文、根拠の付箋のID |
| 望ましい姿 | 1文、指標 |
| 解決案 | 文、理由、元にしたアイデアの付箋のID（AI参加者の案か本人の案か） |
| ストーリー | 本人が確定した文 |
| 効果の見通し | 事例、効果の幅、出典、前提（AIが作ったと明記）。**あとで設計する** |

どの項目も、**本人が〔これで決める〕を押したときだけ書き換わり**、前の版も残す（戻すため、あとで経緯を見るため）。

### 7.4 AIの実行記録

| 項目 | 中身 |
|---|---|
| 役・きっかけ | どの役が、何をきっかけに動いたか |
| 入力の版 | どの版のボードを読んだか、どの版の指示文か |
| モデル | 使ったモデル |
| 出力 | AIが返したそのままの出力 |
| 渡した資料 | 渡した抜粋の記号と、返事で示された記号 |
| 確かめの結果 | 反映したか、捨てたか（理由） |
| 速さ・費用 | かかった時間、トークン数、キャッシュに乗った量 |

### 7.5 データの決まり

- **AIの出力は、決まった形に合っているか、指している付箋のIDが実在するか、版が古くないかを確かめてから反映する。** 形の定義は、画面とサーバーで共有する
- 付箋は、セッションの中に埋め込まず、**別のまとまり（コレクション）で持つ。** 書記と本人が同時に書き換えるので、1枚ずつ版を管理するため
- 音声は保存しない（文字だけ残す。会議室と同じ）
- **AIの実行記録は必ず残す。** 費用と速さを測るためと、「どの付箋をどれだけ掘り下げたか」の偏り（誘導）をあとで確かめるため
- 何日残すかは未決（会議室は30日）

## 9. 試作で確かめたこと（2026-11-01）

画面のたたき台（https://claude.ai/artifact/27qEFKQDQbJkAqfR6QwoyV ）で、Claude を各役のAIとして使い、デモ（台本の発言）を最後まで1回通した。お題と資料は試作用の架空のもの。

### 9.1 わかったこと

| 項目 | 結果 |
|---|---|
| 全体 | AIを呼んだ42回のうち41回が Claude。約2分40秒で最後まで進んだ |
| 待ち時間（実測） | ファシリテーター（速い型）中央値4.2秒・最大9.9秒、書記（速い型）3.6秒、点検係（速い型）2.9秒、AI参加者（じっくり型）1.7秒、編集者（じっくり型）5.7秒 |
| 同時に呼ぶ型（型C） | 問題なく回った。ファシリテーターが実在しない付箋を指すことはなかった。1回遅れの点検結果も自然に次の問いに使われた |
| ファシリテーター | 資料の範囲で答え、本人の言葉を引き、問いは1つ、結論やほめ言葉なし。ただし「広げる」問いが出ない、次への案内を問いの前に挟む、自分で書き直すと申し出る、受け止めの言い回しが同じ、があった |
| 書記 | 引用はすべて発言のとおり。「理由？」の印と、答えが出たら書き足して印を外す動きもできた。ただし**課題・望ましい姿から数字や時期を落とした**（「週に3日ほど」「3年後」）。付箋の種類を日本語で返し、捨てられた付箋が1枚あった |
| 点検係 | 指摘は鋭いが、**同じ案への判定がぶれた**。付箋の本文だけを見て、元の発言を見ていなかった |
| 整理係 | 返事の中でJSONを書き直し、2つ入ったため読めなかった（台本で代わりにした） |
| AI参加者 | 3人の芯の違いがはっきり出た。ソラの課題の問い直しも狙いどおり |
| 編集者 | 決めたことにない事実を足さず、求められた部分だけ直した |

### 9.2 直したこと（同じ日に反映）

| 直したところ | 中身 |
|---|---|
| 書記 | 数・時期・頻度・人数は省かない。質問だけの発言からは付箋を作らない。日本語で返された種類は、プログラムで読み替える |
| 点検係 | 元の発言と補足も読ませる。じっくり型にする（裏で動くので、本人は待たない） |
| 整理係 | 返事にJSONが複数あれば、最後に読めたものを使う。指示文にも「最後にJSONを1つだけ」と書く |
| ファシリテーター | 問いの種類（掘り下げ／広げる）はプログラムが決めて渡す。次への案内は最後に1文。自分で書き直すと申し出ない。受け止めの言い回しを変える。AI参加者の問い直しを本人に渡す |
| 記録 | 直前の発言を掘り下げたときは、その発言から書記が作った付箋に「掘り下げた」を数える |
| 資料係 | 新しく加えた（4.3） |

### 9.3 設計への学び

- **書記の要約は、数字や時期などの具体的な部分を落としやすい。** 落ちると、点検係の判定と、確定する課題にまで影響する。「数・時期・固有の言葉は残す」を書記の決まりにした
- **1回のAIの判定はぶれる。** 裏で動く役は、速さより安定を取る
- **型C（同時に呼ぶ）は、実際の会話でも問題なく回る。** ファシリテーターが直前の発言を掘り下げるのは、会話として自然
- **AIの出力は、形・ID・引用をプログラムで確かめる作りが効いた。** 書記の種類の取り違え、渡していない資料の指し示しを、会話を止めずに捨てられた
