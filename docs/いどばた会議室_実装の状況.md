## 0. ひとことで

- 1人で20分を通して試せる会議室（L1）の上に、**AIメンバーの中身**と、**いどばたの声を読む足す層**を作った
- **本物のAI（OpenAI）では、まだ一度も動かしていない。** このクラウド環境から `api.openai.com` に届かず、APIキーもないため。確認は、決まった返答を返す偽のAIで行った
- いどばた本体の処理とデータは変えていない（足す層は読むだけ。既定では動かない）

## 1. できていること

### 1.1 会議室（20分の打ち込み）

| 機能 | 中身 | 場所 |
|---|---|---|
| 10工程の進行 | お題 → 書き出す → みんなの声 → 課題 → アイディア → 決める → ストーリー → スライド → 壁 | `services/kaigi/steps.js`・`turn.js`、`routes/kaigiRoutes.js` |
| 発言1回にAI呼び出し1回 | AIが4人いても、ファシリテーターが指名した1人の発言だけを作る | `services/kaigi/turn.js` |
| 指示文の並び | 変わらない先頭 → その参加者の20分で固定したもの → 会話の履歴 → 毎回変わる末尾（キャッシュを効かせる） | `services/kaigi/prompts.js`（`buildTurnSystemPrompt`・`buildSessionBlock`・`buildTurnContext`）、`turn.js`（`buildMessages`） |
| 受け答え | 参加者の反応（短い・わからない・長文・意見を求める・反論・感情・脱線など）ごとの応じ方。発言の前に読み取り（`read`）を書かせる | `prompts.js` の `RESPONSES` |
| 話す人の偏りを防ぐ | 工程ごとの発言回数、まだ話していないメンバー、工程6のちゃぶ台返しの有無を数えて添える | `prompts.js` の `speakerBalance` |
| 問い詰める強さ | 参加者が工程4〜8で「やさしく／ふつう／きびしく」を選ぶ。変わるのは言い方だけ | `KaigiSession.intensity`、`PUT /api/kaigi/sessions/:id/intensity`、画面 `IntensitySwitch.tsx` |
| 壁・Google 連携 | 提案スライドの掲示、Meet の予定と記録の取り込み | （L1 から。[`設計_v2.md`](./いどばた会議室_設計_v2.md) 14章、[`Google連携.md`](./いどばた会議室_Google連携.md)） |

### 1.2 AIメンバー3体（[`キャラと論点カード.md`](./いどばた会議室_キャラと論点カード.md) 2章）

| 層 | 中身 | 固定か | 場所 |
|---|---|---|---|
| 芯 | 譲れないこと・大切にしたいこと。ミナミ（肯定派）・ケンジ（否定派）・ソラ（未定派） | どのお題でも同じ | `services/kaigi/personas.js` の `MEMBERS` |
| 肩書き | お題の場に合う肩書き（例：否定派・管理費を預かる理事） | お題ごと | `personas.js` の `ensurePersonas`、`KaigiRoom.personas` |
| 経験と感情 | いどばたの実際の声（自分の経験に基づく声の理由）から、芯に合う出来事として作る | お題ごと | `services/kaigi/cast.js` の `ensureCast`、`KaigiRoom.cast` |
| 軸ごとの判断 | 賛成・反対・決めかねるが混ざる。軸が2つ以上なら、傾きが一番多く、少なくとも1つは別 | 最初はお題ごと | `cast.js` の `enforceMix` |
| 判断の変化 | 新しい情報を聞いたときだけ、話しているメンバーの1つの軸が変わる。理由を口に出し、記録する | 20分の中で変わりうる | `turn.js` の `applyJudgment`、`KaigiSession.judgments`・`judgmentLog` |
| 20分の固定 | 参加者が工程4に入った時点の軸カード・経験・判断を写す | その人の20分は固定 | `KaigiSession.axesAtStart`・`castAtStart`・`overviewAtStart` |

### 1.3 いどばたの上に重ねる足す層（本体は読むだけ）

| 層 | 中身 | 動かし方 | 場所 |
|---|---|---|---|
| 声のプロフィール | 課題・解決策ごとに、立場・根拠・理由・大事にしていること・懸念・対応する課題 | `scripts/profileVoices.mjs`、または `VOICE_PROFILE_SCHEDULE` | `models/VoiceProfile.js`、`services/voiceProfile/`（[`声のプロフィール.md`](./いどばたの声のプロフィール.md)） |
| テーマの3軸 | テーマごとに、問いごとの論点分析から合意・対立の軸（最大3）。声を各側に結びつける。版を持つ | `scripts/buildThemeAxes.mjs`、または `THEME_AXES_SCHEDULE` | `models/ThemeAxes.js`、`services/themeAxes/builder.js`（[`キャラと論点カード.md`](./いどばた会議室_キャラと論点カード.md) 4章） |
| お題の軸カード | お題に近いテーマをAIが選び、関係する軸をお題の言葉で言い直す。各側の声を3件まで添える | お題をつくったとき・工程4に入るとき（自動） | `services/kaigi/roomAxes.js`、`KaigiRoom.themeLink`・`axes`（同 5章） |

- 差分で追いかける：声のプロフィールは文のハッシュ、テーマの3軸は分析の版と声の数の段階で、変わったものだけ作り直す
- 軸カードがないとき（テーマが紐づかない、関係する軸がない）は、工程3の「みんなの声の整理」の対立点を仮の論点にする

### 1.4 ホスト用の画面

| 機能 | 場所 |

| 「AIメンバーが立つ論点」：紐づいたテーマと軸カードを表示（参加者には出さない）。「このテーマを外す」「テーマを探し直す」 | `frontend/src/components/kaigi/ThemeAxesCard.tsx`、`DELETE /api/kaigi/rooms/:id/host/theme`、`POST .../host/theme/relink` |

## 2. 確かめたこと

| 確かめ方 | 結果 |
|---|---|
| バックエンドのテスト（`idea-discussion/backend`、`npx vitest run`。MongoDB が必要） | **93件すべて通過**（2026-10-19）。うち会議室と足す層：`kaigiLogic` 26件、`kaigiRoutes` 7件、`kaigiGoogle` 8件、`voiceProfile` 6件、`themeAxes` 7件 |
| いどばた本体への影響 | 本体のテストは変更の前後で同じく通過。足す層のテストで「本体のデータが1文字も変わらない」ことを確かめている。本体のファイルには変更なし |
| 画面の型チェック・lint | 通過 |
| 偽のAIでの画面確認 | 参加者の画面（工程4、強さの切り替え、肩書きの表示）とホスト用の画面（論点の表示、外す・探し直す）を、パソコン幅とスマホ幅（390px）で確認 |

テストで確かめている主なこと：

- 指示文の変わらない先頭が、20分のあいだ1文字も変わらない
- 軸カードと経験が、先頭と会話の履歴のあいだに入る
- 判断の混ぜ方の決まり（全部同じ側にならない、傾きが一番多い）
- 判断は、理由があり、話しているメンバーの、今ある軸のときだけ変わり、記録される
- テーマを選び、軸カードと元の声を付け、工程4で固定する
- 声のプロフィールとテーマの3軸は、元が変わったときだけ作り直し、AIが失敗しても止まらない

## 3. 確かめていないこと（本物のAIが必要）

| # | 確かめること |
|---|---|
| 1 | 20分で10工程を終えられるか、工程ごとの所要時間（設計 v2 12.3） |
| 2 | 1人あたりの原価と、キャッシュに乗る量（`llmService` のログの `cached=`） |
| 3 | 3体が、芯・経験・判断から話し分けるか。判断が新しい情報で（だけ）動くか |
| 4 | お題に近いテーマの選び方、軸カードの言い直し、経験の作り方が自然か |
| 5 | 声のプロフィールの読み取り（立場・根拠・理由）が正しいか |
| 6 | テーマの3軸が、こしらえた対立を含まないか。声の仕分けが正しいか |
| 7 | 「きびしく」が強すぎないか |

### 試す順番（OpenAI に届くようになったら）

1. `node scripts/profileVoices.mjs --theme <ID> --limit 10`（声のプロフィール。少しだけ）
2. `node scripts/buildThemeAxes.mjs --theme <ID>`（テーマの3軸）
3. 会議室でお題をつくり、ホスト用の画面で紐づいたテーマと軸を確かめる
4. 参加者として20分を通す

本番のデータで試すときは `railway run` を付ける。どれも OpenAI の利用枠をいどばた本体と共有するので、授業のない時間帯に行う。

## 5. 設定（backend の環境変数）

| 変数 | 既定 | 内容 |
|---|---|---|
| `OPENAI_API_KEY` | なし | AIの呼び出しに必要（いどばた本体と共通） |
| `KAIGI_HOST_PASSWORD` | `dd`（暫定。本番で未設定ならお題の作成を止める） | お題をつくるためのパスワード |
| `KAIGI_RETENTION_DAYS` | 30 | お題と関係するデータを自動で消すまでの日数 |
| `KAIGI_LLM_CONCURRENCY` | 20 | 会議室からAIへの同時問い合わせの上限（超えたら順番待ち） |
| `GOOGLE_CLIENT_ID`・`GOOGLE_CLIENT_SECRET`・`KAIGI_GOOGLE_REDIRECT_URI`・`KAIGI_GOOGLE_TOKEN_KEY`・`KAIGI_FRONTEND_URL` | なし | Google 連携（[`Google連携.md`](./いどばた会議室_Google連携.md)） |
| `VOICE_PROFILE_SCHEDULE` | なし（動かない） | 声のプロフィールを定期的に作る（例：`*/30 0-6 * * *`） |
| `VOICE_PROFILE_LIMIT` | 20 | 1回に処理する抽出元の数 |
| `THEME_AXES_SCHEDULE` | なし（動かない） | テーマの3軸を定期的に作り直す。声のプロフィールの後に動かすとよい |
| `BATCH_TIMEZONE` | `Asia/Tokyo` | 定期実行の時刻の数え方（いどばた本体と共通） |
| `KAIGI_TEST_MONGODB_URI` | `mongodb://127.0.0.1:27017/...` | テスト用の MongoDB |

## 6. データ（MongoDB）

| コレクション | 持ち主 | 中身 | 消える時期 |
|---|---|---|---|
| `kaigirooms` | 会議室 | お題、肩書き（`personas`）、紐づいたテーマ（`themeLink`）、軸カード（`axes`）、3体の経験と最初の判断（`cast`）、みんなの声の整理 | お題の期限（TTL） |

| `voiceprofiles` | 足す層 | 声のプロフィール | 元の声が消えたら消す |
| `themeaxes` | 足す層 | テーマの3軸（版ごと。3つまで残す） | 新しい版ができたら古いものから |
