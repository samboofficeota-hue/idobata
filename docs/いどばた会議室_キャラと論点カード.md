# いどばた会議室 3体のキャラとテーマの3軸

> 作成日：2026-10-19 ／ 改訂：2026-10-19（問い1つの論点に乗る案から、テーマ全体の3軸に乗る案へ）
> ステータス：**3体の役割を決め、実装した（2章）。テーマの3軸は未実装**（それまでは、工程3の「みんなの声の整理」の対立点を仮の軸にしている）
>
> 設計の原則は [`いどばた会議室_設計思想.md`](./いどばた会議室_設計思想.md)。

## 1. 決めたこと

| # | 論点 | 決定 |
|---|---|---|
| 1 | AIメンバー3体 | **ほぼ固定。肯定派・否定派・未定派**（強弱の調整はあっても、この3つは変わらない） |
| 2 | 何に対して肯定・否定するか | **論点（対立軸）に対して。** 軸ごとに、肯定派は肯定側、否定派は否定側に立つ。未定派は決めきれないところに立つ |
| 3 | いどばた本体の論点 | **そのまま触らない。** 問いごとの論点・合意・対立（`DebateAnalysis`）は読むだけ |
| 4 | 会議室が立脚するもの | **テーマ全体の3軸。** 本体の問いごとの分析と並行して、テーマ全体としての合意・対立の軸を別に作る |
| 5 | 3軸の範囲 | **テーマごと**（テーマをまたぐと、別々の場の声が混ざるため） |
| 6 | 合意の持ち方 | **軸ごとに、合意と対立を持つ。**「ここまではみんな同じ（合意）、ここから分かれる（対立：肯定側／否定側）」 |
| 7 | 軸の数 | **最大3つ。** 対立が少なければ1〜2軸でよい。対立をこしらえない |
| 8 | お題に合わせた立場づくり | **肩書きだけ残す。**「否定派のケンジ（管理費を預かる理事）」のように、お題に合う肩書きを付ける |
| 9 | 3体の役割の細部 | **2章のとおり**（未定派は迷っている一員として話す、口調を分ける、同じ側のメンバーは根拠を固める、軸の外の話は未定派がつなぐ） |

## 2. 3体の役割（2026-10-19 決定・実装済み）

| | 肯定派 ミナミ | 否定派 ケンジ | 未定派 ソラ |
|---|---|---|---|
| 軸の上の位置 | 肯定側 | 否定側 | 合意を足場に、決めきれないところ |
| 目的 | 参加者の考えを、人に通じる強さまで育てる | 参加者の考えの弱いところを、本番の前に見つける | 参加者が「そもそも何を決めるのか」を見失わないようにする |
| どんな人として話すか | 肯定側の理由・経験・声で後押しする人 | 否定側の理由・懸念・声で突く人 | **両方に一理あると感じて本当に迷っている、その場の一員**。「私はまだ決められないんですが…」と自分の迷いを出す |
| 主に使う材料 | 肯定側の声（理由・経験）、その案が答えている課題、合意点 | 否定側の声、懸念、当事者や別の立場の声、費用・手間・前例などの制約 | 合意点、決めきれない理由（判断に足りない情報）、まだどの案も答えていない課題 |
| 得意な問い | 「それで誰が、どう助かりますか？」「その経験を、もう少し具体的に教えてください」「その理由で、反対する人を説得できそうですか？」 | 「それに反対する人は、何と言うと思いますか？」「お金と手間は、誰が持ちますか？」「それで困る人はいませんか？」 | 「みんなが同意しているのは〇〇ですよね。そこから考えると？」「それを決めるのに、何が分かれば決められますか？」「そもそも、決めたいのはどちらのことでしょう？」 |
| 口調 | 温かく、受け止めてから問う | 率直に、短く | 素朴に、迷いを隠さずに |
| しないこと | 根拠のない褒め言葉、参加者の代わりに案を作ること | 人格や言い方を責めること、代案を押しつけること | どちらかの側に立つこと、自分の結論を出すこと |
| 出番が多い工程 | 6（アイディアを広げる） | 7〜8（行ったり来たり、決める） | 4〜5（課題を絞る、言葉にする）、6（ちゃぶ台返し） |

- 口調はどれも丁寧語。3体で口調を分け、誰が話しているかが文から分かるようにする
- お題に合わせて変えるのは**肩書きだけ**。画面と指示文では「否定派・管理費を預かる理事」のように出る。肩書きを作れなかったときは「否定派」だけ
- **ファシリテーター**は3体とは別の進行役。誰が話すかの指名と、時間の管理を受け持つ

### 2.1 論点への立ち方のルール

| 場面 | ふるまい |
|---|---|
| ふだん | 3体は論点ごとに立つ。肯定派は肯定側、否定派は否定側、未定派は合意を足場に決めきれないところ |
| 20分のあいだ | **立ち位置を変えない。** 前に言ったことと逆のことを言わない。考えを言い直すときは、何を聞いてそう思ったのかを言う |
| 参加者の考えが、ある側と同じとき | **同じ側のメンバーは、同意だけで終わらず根拠を固める**（「その理由で、反対する人を説得できそうですか？」）。反対側のメンバーは、その考えの弱いところを問う。否定側と同じときも同じ扱い（ケンジが根拠を固める） |
| 参加者の話が、どの論点にも近くないとき | **未定派が論点につなぐ**（「それは、みんなが分かれている〇〇の話と、どう関係しますか？」）。つながらなければ、それも新しい課題として扱う |
| 強さ（やさしく／ふつう／きびしく） | 変わるのは問いの言い方だけ。役割と立ち位置は変えない。「きびしく」ではケンジは反例や数字を求め、ソラは前提を遠慮なく疑う。「やさしく」ではミナミが受け止めてから、ケンジとソラが問う |

### 2.2 実装

| 内容 | 場所 |
|---|---|
| 3体の役割の定義（目的・材料・得意な問い・口調・しないこと） | `idea-discussion/backend/services/kaigi/personas.js` の `MEMBERS` |
| お題に合わせた肩書き（お題1つにつき1回作る） | 同 `ensurePersonas`、`KaigiRoom.personas.member*.title` |
| 論点への立ち方と、話す人の選び方 | `services/kaigi/prompts.js` の `AXIS_STANCE`・`SPEAKER_GUIDE`（指示文の変わらない先頭に置く） |
| 仮の軸（テーマの3軸ができるまで） | 工程3の「みんなの声の整理」の対立点と合意点。**参加者が工程4に入った時点のものを `KaigiSession.overviewAtStart` に固定**し、20分のあいだ使い続ける |
| 画面の表示 | 会話の吹き出しの名前の横に「肯定派・肩書き」 |

- 指示文の変わらない先頭は、約2,900字から約4,000字に増えた。毎回キャッシュに乗る部分なので、原価への影響は小さい見込み（未実測）。毎回変わる末尾は、役割の説明を先頭に移したので約840字から約570字に減った
- **本物のAIで、3体が役割どおりに話し分けるかは、まだ確かめていない**

## 3. 全体の形

```
いどばた本体（触らない）              新しく足す層                       会議室
──────────────────              ──────────────                  ──────
問いA の DebateAnalysis ─┐
問いB の DebateAnalysis ─┼─▶ テーマの3軸（ThemeAxes・版あり）─▶ お題に合わせて言い直す ─▶ 3体が立つ
問いC の DebateAnalysis ─┘        ▲                                 （お題の軸カード）
                                  │
Problem / Solution ＋ 声のプロフィール ─┘ 各軸の肯定側・否定側・未定に、元の声を結びつける
```

- 本体の問いごとの分析は、そのまま残る。テーマの3軸は、その**上に重ねる別の層**
- 声のプロフィール（[`いどばたの声のプロフィール.md`](./いどばたの声のプロフィール.md)）と同じく、本体のデータは読むだけで、書き込むのは新しいコレクションだけ

## 4. テーマの3軸（ThemeAxes）

### 4.1 中身

テーマ1つにつき1組（最大3軸）。作り直すたびに版を上げる。

| 項目 | 中身 |
|---|---|
| 軸 | 「〜すべきか」の形の一文（例：共用自転車を残すべきか） |
| 合意 | この軸で、ほぼ全員が同じ考えのところ（例：通路の安全は守るべき） |
| 肯定側の主張 | 肯定派が立つ側の考え。1〜2文 |
| 否定側の主張 | 否定派が立つ側の考え。1〜2文 |
| 決めきれない理由 | 未定派が立つところ。判断に足りない情報、両方に一理あるところ |
| 肯定側の声・否定側の声 | その側に立つ、いどばたの声（課題・解決策）のID。プロフィールで立場・根拠・理由を引ける |
| 未定の材料 | どの案も答えていない課題、根拠が「考え・推測」や「不明」の声 |
| 出どころ | 元にした問いと、その `DebateAnalysis` の版。軸ごとに、どの問いの論点から来たかをたどれるようにする |

### 4.2 作り方

1. テーマの問いごとの `DebateAnalysis`（それぞれ最新版）を集める
2. 骨組みを作る：問いごとの対立軸・合意点・対立点を読み、テーマ全体として重要な対立を**最大3軸**にまとめる。軸ごとに、合意・肯定側・否定側・決めきれない理由を書く
3. 声を結びつける：テーマの声（課題・解決策）を、プロフィールの理由・懸念・対応する課題も見ながら、各軸の肯定側・否定側・未定に仕分ける
   - 懸念（`concern`）の付いた解決策は、その案に反対する側の材料になりやすい
   - どの軸にも関係しない声は、どこにも入れない
4. 保存する（新しいコレクション。例：`ThemeAxes`）

- **まとめのまとめでずれないように**、骨組みは分析から作り、各側の中身は元の声に結びつける。会議室のキャラが話す根拠は、要約ではなく元の声
- AIの呼び出しは、骨組みに1回、声の仕分けに声の量に応じて数回（見積もり）

### 4.3 作り直し

- テーマの問いの `DebateAnalysis` の版が上がったとき、または声が一定数増えたときに作り直す
- 声のプロフィールと同じく、定期的に動かす（授業のない時間帯。既定では動かない）
- 作り直すたびに版を上げ、古い版も一定期間残す（20分の途中の参加者が、始めた時点の版を使い続けられるように）

## 5. 会議室での使い方

```
① お題をつくるとき
   お題に近いテーマを AI が探して紐づける（ホスト用の画面に表示し、ホストが外せる）
   → テーマの3軸のうち、お題に関係する軸を選び、お題の言葉で言い直す（お題の軸カード）

② 参加者が20分を始めるとき
   その時点の版のカードを、その人の20分のあいだ固定する

③ 発言のたび
   参加者の話に一番近い軸を選ぶ
   → 話すキャラの側（肯定側／否定側／未定）の声・資料だけを探して渡す
```

- テーマの3軸は、お題より広いことが多い。①で、**お題に関係しない軸は使わない**
- 紐づくテーマがないとき、またはお題に関係する軸がないときは、会議室の「みんなの声の整理」の対立点から、お題の軸カードを作る
