# いどばた会議室 AIが読む情報

> 作成日：2026-10-19 ／ 改訂：2026-10-19（写しを持つ案から、最新を参照する案へ）
> ステータス：**一部実装。** 指示文の並び（4章）と、いどばたの論点・声を「お題の軸カード」として渡す部分（[`いどばた会議室_キャラと論点カード.md`](./いどばた会議室_キャラと論点カード.md) 5章）は実装済み。ホストの資料（3.5）と、発言のたびに探して渡す仕組み（3.1〜3.4、5章）は未実装。今の状況は [`いどばた会議室_実装の状況.md`](./いどばた会議室_実装の状況.md)
>
> 数字はすべて見積もり（未実測）。
>
> 設計の原則は [`いどばた会議室_設計思想.md`](./いどばた会議室_設計思想.md)。

AIメンバー（ファシリテーター・メンバー3人）が、お題と背景のほかに、ホストの資料と、いどばたの論点・実際の声を読んで話せるようにする。

**前提：** いどばたでは、参加者が書き込む声も、それを分析した論点も、**どんどん増え、書き換わっていく**。AIはいつも、その時点の最新を読まなければならない。

## 2. 最初の案の問題（なぜ改めたか）

最初の案は、お題をつくった時点で、いどばたの声を写して保存するものだった。点検すると、次の問題があった。

| 問題 | 中身 |
|---|---|
| 声が古くなる | お題をつくった後に増えた声を、AIが読まない |
| 分析が古くなる | `DebateAnalysis` は作り直すたびに版が上がる（`services/debateAnalysisGenerator.js`）。写しは古い版のまま |
| 問いが固定される | 近い問いを探すのが1回だけ。後からできた、より近い問いに切り替わらない |
| いどばたの検索データに頼れない | python-service（Chroma）の検索データは、管理画面から操作したときしか作られない。また、声の文章が書き換わって版が上がっても（`workers/extractionWorker.js`）「作成済み」の印が残り、**古い文章のまま**になる |
| 検索の使い方が粗い | 直前の発言だけで探すので、「はい」のような短い返事では外れる。関係が薄くても毎回4件渡すので、AIが無理に触れる。同じ情報を何度も出す |
| キャッシュが効かない | 指示文の先頭に、毎回変わる残り時間が入っていた。OpenAI のキャッシュは先頭から同じ部分にしか効かないので、毎回すべてを割引なしで払っていた（**4章で直した**） |

## 3. しくみ：最新を参照する層

```
いどばた（増える・変わる）                会議室の参照層                         AIへの1回の呼び出し
──────────────────────                ──────────────────                  ─────────────────────
SharpQuestion（問い）  ──差分──▶  問いの検索データ ──▶ 近い問いを選ぶ
DebateAnalysis（最新版）─────────────────────────────▶ 対立軸・合意点 ─────▶ 末尾にそのまま
Problem / Solution     ──差分──▶  声の検索データ  ──▶ 近い声を探す   ─┐
ホストの資料（変わらない）──1回──▶  資料の断片     ──▶ 近い断片を探す ─┴──▶ 末尾に0〜4件
```

### 3.1 検索データの持ち方

検索用のベクトルは、会議室の側で MongoDB に持つ（新しいコレクション、例：`KaigiRefVector`）。

| 項目 | 内容 |
|---|---|
| 元のデータ | 種類（問い／課題／解決策／資料の断片）と、元のID |
| 指紋 | 元の文章のハッシュ（SHA-256）。**文章が書き換われば指紋が変わる** |
| ベクトル | `text-embedding-3-small`（いどばたの python-service と同じモデル） |
| 削除 | 資料の断片はお題と同じ日に自動で削除（TTL）。いどばたの声と問いは複数のお題で共有するので、元がなくなったものを差分の更新で消す |

- 既存の python-service（Chroma）は使わない。いどばたの声の書き換えに追いつかないうえ、削除の窓口がないため
- 件数は、お題1つにつき資料の断片が数百、いどばたの声が数百〜数千の見込み。**MongoDB から読んでサーバーの中で総当たりで比べる**。1万件を超えたら、MongoDB Atlas のベクトル検索などへ移す（そのときは比べる部分だけを差し替える）

### 3.2 差分の更新（いどばたが増え・変わっても追いつく）

1. 対象の声（問いに紐づく `Problem` / `Solution`）の `statement` から指紋を作る
2. 保存してある指紋と比べ、**新しいもの・指紋が変わったものだけ**ベクトルを作り直す。元がなくなったものは消す
3. 更新するのは次のとき
   - 参加者が20分を始めるとき（`/start`）
   - 工程3の「みんなの声の整理」を作り直すとき
   - 同じ問いの更新は、5分に1回まで（同時に何人が始めても1回）
4. 更新が失敗しても、20分は止めない。手元にある検索データで続ける

費用：ベクトル化は1,000件で約0.1円（見積もり）。差分だけなので、ふだんは0件〜数十件。

### 3.3 近い問いを選ぶ（問いが増えても追いつく）

- お題をつくるときと、**参加者が20分を始めるたびに**選び直す
- 問いの検索データも 3.2 と同じく差分で更新する（公開中の問い `isVisible` だけ）
- 一番近い問いが、決めた近さ（しきい値）を超えたら紐づける。超えなければ紐づけない
- どの問いに紐づいたかはホスト用の画面に出す。**ホストが外したら、自動では紐づけ直さない**
- ある参加者の20分のあいだは、始めたときの問いを使い続ける（途中で論点が入れ替わらないように）

### 3.4 論点の分析は使うたびに最新を読む

- `DebateAnalysis` は、紐づいた問いの**最新の版**を読む。読んだものは5分間だけ使い回す
- 対立軸・合意点・対立点は短いので、探さずに毎回そのまま渡す

### 3.5 ホストの資料

- お題をつくるときにアップロードする。PDF・Word（.docx）・テキスト。上限は5ファイル・合計20万字（叩き台）
- 400字ほどの断片に分けて、ベクトルにする。資料は変わらないので、取り込みは1回
- 文字を取り出せない資料（スキャンした画像だけのPDFなど）は、その旨をホストに伝えて受け付けない

## 4. 指示文の並び（2026-10-19 実装済み）

```
[先頭] 役割・お題・背景・参加者・AIの立場・工程ごとの目的・ルール・応じ方・強さの説明   ← 20分のあいだ変わらない
[履歴] 会話（増えていくだけで、前の部分は変わらない）
[末尾] 今の工程・話してよいAI・残り時間・決まったこと・みんなの声・発言の回数・今の強さ・出力形式   ← 毎回変わる
       （ここに、探した情報と論点の分析を足す）
```

- 先頭と、履歴の前の部分が、毎回キャッシュに乗る。先頭だけで約2,900字あり、キャッシュが効く最低量（1,024トークン）を超えている
- 探した情報は**必ず末尾に置く**。先頭に置くと、毎回キャッシュが切れる
- 場所：`idea-discussion/backend/services/kaigi/prompts.js`（`buildTurnSystemPrompt` と `buildTurnContext`）、`turn.js`（`buildMessages`）

## 5. AIへの渡し方（RAGを使いこなすために）

| 工夫 | 中身 |
|---|---|
| 探す手がかり | 直前の発言だけでなく、**直前の発言＋直前のAIの問い＋決まった3点**で探す。「はい」だけでも外れにくい |
| 工程で探すものを変える | 工程4〜5は課題（`Problem`）と資料、工程6〜7は解決策（`Solution`）と資料、工程8は資料だけ。工程2は探さない（自分の考えを出し切ってもらう工程なので） |
| 近さの基準 | 基準に届いたものだけ、最大4件。**届かなければ何も渡さない** |
| 出どころを付ける | 「資料『管理規約.pdf』より」「いどばた（別の場）の声・2026-10-12」のように、出どころと日付を付けて渡す |
| 使い回さない | その参加者の20分の中で、一度渡したものは次から外す |
| 渡す量 | 合計1,600字まで |

### 5.1 AIの使い方のルール（指示文に書く）

- 探した情報は**使わなくてよい**。話の流れに合うときだけ使う
- 資料に触れるときは、出どころが分かる言い方をする（「規約では〜とあります」「別の場では〜という声がありました」）
- 資料にないことは推測で言わない。「資料にはありません」と言う
- 資料の内容で参加者の意見を否定しない。問いの材料として使う
- いどばたの声は、このお題の参加者の声ではないことを踏まえて扱う
- 資料の文章を長く引き写さない（AIだけが読む資料なので）

### 5.2 使いこなせているかを測る

本物のAIで確かめるために、発言ごとに次を記録する（参加者の発言そのものは記録に残さない）。

- 何件探して、何件渡したか、それぞれの近さ
- AIがそれを使ったか（返答の `read` に、使った情報の番号を書かせる）
- 1回の呼び出しの入力トークンのうち、キャッシュに乗った量（`llmService` のログの `cached=`）

## 7. 「AIだけが読む」ことの注意

- 資料そのものは画面に出さないが、AIは会話の中で資料の内容に触れる。**内容の一部は参加者に伝わる**
- お題をつくる画面に「参加者に知られて困る情報が含まれる資料は入れないでください」と表示する
- いどばたの声は `statement`（抽出・要約された文）だけを使う。誰が言ったかの情報（`sourceMetadata` など）は読まない
