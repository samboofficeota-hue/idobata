# ひとりいどばた 体験の流れ

> 作成日：2026-11-01
>
> 本人がひとりで、お題について考え、課題・望ましい姿・解決案を自分の言葉でまとめるまでの流れ。
> AIをどう組み合わせるか（誰が・いつ・何をするか）とデータの持ち方は、[`AIの組み合わせとデータ`](./ひとりいどばた_AIの組み合わせとデータ.md) にまとめた。
> 考え方の土台は [`設計の考え方`](./ひとりいどばた_設計の考え方.md)、根拠にした事例は [`先行事例調査`](./ひとりいどばた_先行事例調査.md)。

---

## 0. ひとことで

- お題を理解し、意見を出し切り、課題と望ましい姿を自分の言葉で決め、解決案を選び、ストーリーにまとめる
- 終わったら、**本人の手元にドキュメントが残る。** 壁やホストに届けるかは本人が決め、操作も本人がする
- AIは、問う・記録する・整理する・案を出す。**課題も望ましい姿も解決案も、決めるのは本人**

## 2. 流れ

| 段階 | # | 中身 | この段階で確定するもの | 画面 |
|---|---|---|---|---|
| **下準備** | 1 | お題を見る（スライド・テキスト） | — | 必要 |
| | 2 | わからないことを聞く。AIは**資料の範囲だけで**短く答え、意見は言わない | — | |
| | 3 | お題を自分の言葉で一言にする。「気になったこと」を最初の付箋にする | お題の理解（一言） | |
| **意見出し** | 4 | 意見・経験・気持ちを話す（音声かテキスト） | — | なくてもよい |
| | 5 | 書記が付箋にして貼る（本人の言葉から作り、元の発言にたどれる） | 意見の付箋 | |
| | 6 | ファシリテーターが、広げる・掘り下げる（1回に1問） | — | |
| | （空き） | みんなの声を、別の色の付箋で重ねる（**あとで加える**） | — | |
| **課題整理** | 7 | 〔まとめる〕でボードを整理する（グループ分けは案）。ファシリテーターは「このボードを見て、一番なんとかしたいのはどれですか？」と問う。答えは示さない | — | 必要 |
| | 8 | 本人が、解決すべき課題を言う | — | |
| | 9 | 現状と課題の精度を、対話しながら高める（3.2） | **現状、課題（1文）** | |
| **ゴール設定** | 10 | 望ましい姿を声で示す。ファシリテーターが支える（3.3） | **望ましい姿（1文）と指標** | なくてもよい |
| | 11 | 課題と望ましい姿がつながっているかを確かめる。ずれていたら9か10に戻る | — | |
| **アイデア出し** | 12 | 本人が**先に**アイデアを出す | — | 一部 |
| | 13 | AI参加者がアイデアを足す。「そもそも課題は合っている？」と問い直すこともある。AIのアイデアは付箋の色を分ける | — | |

| **まとめ** | 15 | ストーリーにまとめる（現状 → 望ましい姿 → 課題 → 解決案 → それでどうなるか）。AIが下書きし、本人が直して確定する | **ストーリー** | 必要 |
| | 16 | 似た事例と効果の見通しを、EBPM や研究のデータから、**出典つき・幅つき**で示す（3.5） | **効果の見通し** | |

「画面」は、その段階で画面を見る必要があるか。歩きながら・電車でも使う前提なので、**話すだけで進められる段階**（意見出し、ゴール設定）と、**画面を見られるときにやる段階**（下準備、課題整理、まとめ）がある。

## 3. 全体の決まりと、段階ごとの要点

### 3.1 全体の決まり

| 決まり | 中身 |
|---|---|
| 戻れる | いつでも前の段階に戻れる。アイデアを出しているうちに「課題がずれていた」と気づいたら、課題整理に戻る（会議室の工程7「行ったり来たり」の考え方） |
| 進めるのは本人 | ファシリテーターは「次に進みましょうか」と提案するだけ。本人が〔次へ〕を押して進む。進むのに必要なもの（例：課題が1文で決まっている）は、プログラムで確かめる |
| 中断と再開 | 同じ日なら、途中でやめて続きから再開できる |
| AIの案 | AIが出したもの（整理の案、課題の候補、アイデア、ストーリーの下書き、効果の見通し）は、すべて「案」として見せ、本人の言葉と見た目で分ける。採用するかは本人が決める |

### 3.2 課題の精度（9）

ファシリテーターは、次の点を1つずつ問う。全部を一度に問わない。

| 点検すること | 例 |
|---|---|
| 誰が困っているか | 「住民」ではなく「共働きで小学生の子がいる家庭」 |
| どんな場面で | 「放課後から親が帰るまでの時間」 |
| 何に、どれくらい困っているか | 「週3日、子どもが一人で過ごしている」 |
| なぜ起きているか | 原因（なぜなぜ） |
| 根拠の付箋があるか | ボードのどの意見から来ているか |
| 解決策が混ざっていないか | 「学童が足りない」は解決策の裏返しになりやすい |

あわせて、**現状**（何が起きているか）を言葉にする。15のストーリーの出発点になる。

### 3.3 望ましい姿（10・11）

- 誰が、どうなっているか
- いつごろまでに
- **どうなったらわかるか（指標）**：例「一人で過ごす日が週3日から週1日以下になる」。16の効果の見通しの「ものさし」になる
- 11で、課題と望ましい姿がつながっているかを確かめる。課題を解決すると望ましい姿に近づくか。ずれていたら、9か10に戻る

### 3.4 アイデアの出し方と選び方（12〜14）

- **本人が先に出し、AIは後から加わる。** 研究では、AIのアイデアを先に見ると本人の考えがそちらに寄り、他の人とも似てきて、自分のアイデアだという感覚も下がった（[`先行事例調査`](./ひとりいどばた_先行事例調査.md) 5章）
- AIのアイデアは、付箋の色を分ける。採用しない限り「案」のまま
- 選ぶときの目安：課題に効くか、望ましい姿に近づくか、実現できるか（誰がやるか、費用はどれくらいか）
- 1つに絞っても、組み合わせてもよい

### 3.5 効果の見通し（16）

- ここは**AIが中身を出す唯一の段階。** 課題・望ましい姿・解決案を本人が決めたあとに置くので、本人の判断をAIが先に方向づけることはない
- 似た事例と効果の大きさを、**出典つき**で示す。数字は1つではなく**幅**で示し、前提を書く
- **根拠が見つからなければ「見つからない」と言う。** AIが自分の知識で数字を作らない
- 見て、解決案に戻ってもよい
- 根拠のデータを誰が・どこから用意するかは、まだ決まっていない（7章）。**この段階は、RAG（資料や根拠を探してAIに渡す仕組み）の設計と合わせて、あとで考える**（2026-11-01 決定）

## 5. 手元に残るドキュメント

| 項目 | 中身 | 書いた人 |
|---|---|---|
| お題 | お題の名前と、本人の一言 | 本人 |
| 現状 | 何が起きているか | 本人（AIが整える） |
| 課題 | 1文 | 本人 |
| 望ましい姿 | 1文と指標 | 本人 |
| 解決案 | 選んだアイデアと、その理由 | 本人（AIのアイデアを採用した場合はそれとわかるように） |
| ストーリー | 現状 → 望ましい姿 → 課題 → 解決案 → それでどうなるか | AIの下書きを本人が確定 |
| 効果の見通し | 似た事例、効果の幅、出典、前提 | **AI**（そう明記する） |
| 付録 | ボードの付箋（意見・アイデア） | 本人の言葉から書記が作成 |

- 項目は今の内容で始め、必要なら後から足す
- **届けるとき（案）：** 付箋には本人の経験や個人的な事情が入りやすい。届けるときは付録（付箋）を外すのを初期設定にし、本人が中身を見てから送る

## 6. 段階ごとの「AIがすること」の下書き

次の段階（AIの組み合わせ）を考えるための下書き。まだ決定ではない。

| 段階 | AIがすること | AIがしないこと |
|---|---|---|
| 下準備 | 資料の範囲で質問に答える | 資料にないことを推測で答える。意見を言う |
| 意見出し | 発言を付箋にする。広げる・掘り下げる問いを出す | 意見を足す |
| 課題整理 | ボードを整理した案を出す。課題を点検する問いを出す。頼まれたら課題の候補を案として出す | 課題を決める |
| ゴール設定 | 望ましい姿を描くための問いを出す。課題とのつながりを確かめる | 望ましい姿を決める |
| アイデア出し | 本人のあとで、別の参加者としてアイデアを出す。課題を問い直す | 解決案を選ぶ |
| まとめ | ストーリーの下書き。根拠にもとづく効果の見通し | 根拠のない数字を出す。本人の確定なしにドキュメントを仕上げる |
